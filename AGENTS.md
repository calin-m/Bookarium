# Multi-Agent Development Standards - Bookarium

Welcome to **Bookarium**. When contributing or generating code for this repository, autonomous agents and developers must strictly follow these engineering protocols.

> **Canonical Protocol Specification & Full-Project Map**: For the complete enterprise governance rules and 6-layer system topology, see [`.agents/AGENTS.md`](file:///.agents/AGENTS.md) and [`docs/ARCHITECTURE.md`](file:///docs/ARCHITECTURE.md).

## Core Principles & Boundaries
1. **Rule 0 (User Approval, Pre-Plan Impact Audit & 6-Stage Plan Closure)**: Never modify files, apply architectural shifts, or install dependencies without prior user approval and review. Before drafting any new `implementation_plan.md`, inspect `git status --short` for undocumented pending changes from prior batches, trace interconnected files via the **Inter-Reference Impact Matrix**, and structure every plan in the **6-Stage Logical Execution Order (Zero-Drift Sequence)** (`Stage 0` through `Stage 5`) so approval covers sealing upstream generators and running `npm run docs:sync` in the same batch right after tests pass.
2. **Public Domain Integrity, Multi-Jurisdictional Copyright & Gutenberg Compliance**: Do not introduce any closed-source, DRM-restricted, or copyright-infringing book sources. Ensure all queries pass `copyright=false`, enforce multi-jurisdictional public domain evaluation (`src/lib/copyright-engine.ts`: `US 1930`, `Life+70`, `Life+80`, `Life+100`), preserve authentic author lifespans/names across local stores and IndexedDB (`isPlaceholderAuthor` guardrails so offline books never revert to `"Anonymous"` or trigger false `HTTP 451`), and strictly honor Project Gutenberg policy (individual-only downloads, mirror-first prioritization across `aleph.gutenberg.org`, `gutenberg.pglaf.org`, and `gutenberg.readingroo.ms` ahead of `www.gutenberg.org`).
3. **Zero API Key Requirement & Offline-First PWA Parity**: The core user experience must work without any third-party paid keys, auth sign-in, or backend database setup, and must maintain offline-first PWA resilience (`public/sw.js` `bookarium-app-shell-v7`, `useNetworkStatus`, adaptive offline Catalog fallback, and `isUnavailableOffline` restriction parity for uncached volumes when offline).
4. **State & Offline Architecture**:
   - **Remote data**: TanStack React Query v5 (`useBooks`, `useFeaturedQuotes`, `useQuoteEnrichedBooks`, `useBookContent` with `networkMode: 'always'`, `useBookTranslations`).
   - **Local persistent state (10 Zustand stores)**: `useBookshelfStore`, `useReaderStore`, `useAuthStore`, `useFellowshipStore`, `useAnnotationStore`, `useAccoladesStore`, `useHabitsStore`, `useJurisdictionStore`, `usePreferencesStore`, and `useThemeStore`.
   - **Offline volume cache & cloud sync**: IndexedDB unabridged book storage (`src/lib/offline-storage.ts`, `useOfflineBooks`) and 7-store bi-directional Supabase outbox reconciliation (`src/lib/sync-utils.ts`, `src/lib/bookshelf-cloud-sync.ts`, `src/lib/preferences-sync.ts`).
5. **Co-located Testing, Zero-Any, Zero-Warning & Anti-Regression Accuracy**: Every component (`*.tsx`), hook (`*.ts`), store (`*.ts`), route handler (`route.ts`), domain utility (`src/lib/**`), config (`src/config/**`), Web Worker (`src/workers/**`), and CLI ingestion/sync & security pipeline (`scripts/ingest-*.test.ts`, `scripts/sync-*.test.ts`, `scripts/eslint-rules/bookarium-security.test.ts`) must have a 1:1 co-located `*.test.ts` or `*.test.tsx` testing authentic user journeys with `@testing-library/react` and MSW v2 (`256` suites). Standalone dev, doc, hook, and build runners (`scripts/verify-build.js`, `scripts/generate-*.js`, `scripts/approval-gate.js`) stay outside Vitest and `src/` V8 coverage (`vitest.config.mts`) to avoid circular self-invocation and coverage distortion. Zero synthetic/fake tests, no loose assertions, strict zero-`any` (`@typescript-eslint/no-explicit-any: "error"`), zero ESLint warnings (`--max-warnings 0`), CodeQL-safe relative asset URLs in tests, and mandatory co-evolution on every code change.
6. **Coverage Enforcement**: Never allow test coverage to drop below the configured V8 thresholds (`lines: 95%`, `statements: 95%`, `functions: 92%`, `branches: 85%`).
7. **Git Protocol (Human Execution Only, Live Diff Anti-Drift & `[PHASE]` Truthfulness)**: Provide in-depth structured conventional commit commands (`[PHASE]`, `[WHY]`, `[WHAT]`, `[VERIFICATION]`) only when explicitly requested by the user (citing a Roadmap Milestone in `[PHASE]` only when implementing a planned `ROADMAP.md` deliverable, or `<Descriptive Scope> (v<version>)` for tactical patch work). Before formulating any commit command, inspect **all** live working-tree changes directly from Git (`git status --short`, `git diff HEAD` covering both staged and unstaged tracked deltas, and direct reads of all `??` untracked files) — never draft commit messages from conversation context or prior summaries — and ensure `[WHAT]`/`[WHY]` cover 100% of current pending changes (paired with a concise grouped file summary, printing raw unified patches only when requested) while `[VERIFICATION]` reports only checks observed on the current pending state. AI agents must never execute `git commit` or `git push` directly.
8. **Two-Tier Test Execution, 7-Gateway Quality Engine & Post-Remediation Re-Sync Loop (`Rule 6`)**: Automatically run a consolidated pending-changes check (`npx vitest run <all-pending-and-colocated-test-files>`, `npm run typecheck`, `npm run lint`) across all modified/untracked files in `git status --short` upon completing each plan/batch (Stage 3) prior to Stage 4/Stage 5 and `npm run verify`. Run the full 256-suite `npm test` and 7-Gateway `npm run verify` (Pass 0.5 secret/boundary/env-parity/transitive-AST scanner, Pass 0.75 7-Pillar SAST/OWASP & 9-rule `bookarium-security` AST request-taint suite, and Passes 1–7 including semantic doc parity, 1:1 SQL$\leftrightarrow$TS schema parity, and 100% 1:1 test co-location) when explicitly requested by the user or when debugging a build/coverage error. Whenever a Stage 5 or verification run reveals issues and remediation fixes are applied, loop back through affected Stage 3 checks (`vitest`, `typecheck`, `lint`), revisit Stage 4 docs/architecture generator scripts, and re-run Stage 5 (`npm run docs:sync`, `npm run gate:approve`, `npm run security:audit`) so the post-fix state stays 100% synchronized.
9. **Rule 9 (Idempotent Database Schema Co-Evolution, RLS Governance, Account Deletion Parity & Live SQL Hand-Off)**: All database modifications must co-evolve `supabase/schema.sql`, `src/types/database.types.ts`, `scripts/generate-architecture-matrix.js`, and `README.md` using strictly idempotent SQL (`CREATE TABLE IF NOT EXISTS`, `CREATE INDEX IF NOT EXISTS`, `DROP POLICY IF EXISTS`) with strict Row Level Security enabled across all 14 database tables (13 `public.*` tables + `supabase_migrations.schema_migrations`) (`SET search_path = ''` and `REVOKE EXECUTE ... FROM PUBLIC, anon` on all `SECURITY DEFINER` functions, plus `REVOKE EXECUTE ... FROM PUBLIC, anon, authenticated` on all `RETURNS TRIGGER` functions). Every user-scoped table, column, or local store slice must also maintain 100% account deletion parity (`ON DELETE CASCADE`, explicit purge in `public.delete_current_user()`, fallback deletion in `useAuthStore.deleteAccount()`, and complete local store/device reset in `clearLocalUserStores({ wipeDeviceStorage: true })`). Whenever `supabase/schema.sql` is modified, the agent must output a standalone, copy-paste-ready idempotent SQL migration block directly in chat so the user can immediately execute it in the deployed Supabase SQL Editor.
10. **Rule 1 (Two-Phase Documentation, Inter-Reference Matrix, 78k-Row Index Query Invariants & 6-Stage Zero-Drift Sequence)**:
    - **Never Edit Generated Outputs Directly**: Never manually edit `docs/ARCHITECTURE.md`, `docs/GUTENBERG_PARSER.md`, `CHANGELOG.md`, `ROADMAP.md`, `docs/QUALITY_AUDIT_REPORT.md`, `docs/quality-audit-results.json`, or the auto-generated blocks in `README.md` (`<!-- BEGIN:architecture-diagrams -->`, `<!-- BEGIN:latest-release -->`, top telemetry badges/counts); always update their upstream sources first.
    - **78k-Row `public.books` Index & Query Execution Invariants**: `idx_books_download_count` is a single-column B-Tree index `(download_count DESC)` across 78,000+ rows (`77,500+` with `download_count = 0`). Never chain `.order('id', { ascending: true })` onto `.order('download_count', { ascending: false })` in SQL (perform `id ASC` tie-breaking in memory in JS), and never combine `.neq('quotes', '[]')` with `ORDER BY download_count DESC` without a Primary Key `.in('id', chunk)` bound (`books_pkey`) so PostgREST/PostgreSQL never falls back to a 78,000-row table scan.
    - **SemVer (`x.xx.xx`) Two-Tier Release Cadence, Box-Capacity Auto-Bump & Living ADR Sync**: Maintain `RELEASES[0].version` in `scripts/generate-changelog.js` as the single source of version truth (`npm run docs:sync` automatically propagates it across `package.json`, `package-lock.json`, `CHANGELOG.md`, `README.md` `Latest Improvements`, `ROADMAP.md`, `SECURITY.md`, `.github/workflows/release.yml`, and `.github/ISSUE_TEMPLATE/bug_report.yml`). `ROADMAP.md` tracks macro `MINOR` series (`v2.9.x`, `v2.10.0`) and is edited only when strategic milestone deliverables complete or when requested by the user, while `CHANGELOG.md` tracks tactical `PATCH` releases (`2.9.1`, `2.9.2`... `2.9.12+`) governed by the **Box-Capacity Auto-Bump** in `Pass 5` (**1–6 bullets/release**, **$\le 1,200$ chars/bullet**, **1–3 unique ADRs/release**, and active `major.minor.x` series citation of the latest ADR in `docs/DECISIONS.md`). Continuously audit `docs/DECISIONS.md` on every change, evolving existing thematic ADRs for refinements/extensions, pruning/updating superseded statements in earlier ADRs in place (recording retired subsystems in the `## 🗄️ Decommissioned & Superseded Decisions Ledger` table at the bottom of `docs/DECISIONS.md` and in `scripts/generate-roadmap.js` while preserving contiguous `## ADR-001:`..`## ADR-NNN:` numbering), and reserving new sequential ADRs in `docs/DECISIONS.md` for major new subsystems.
    - **6-Stage Logical Execution Order (Zero-Drift Sequence)**: Execute every approved plan bottom-up: **Stage 0** (`git status --short` & Inter-Reference Impact Audit across schema, `src/`, `.env.example`, `package.json`/`knip.json`/`.agents/hooks.json`, and security gates) $\rightarrow$ **Stage 1** (Contracts, `supabase/schema.sql`, `src/types/`, `.env.example`, configs, workflows) $\rightarrow$ **Stage 2** (Production `src/` & `scripts/` modules) $\rightarrow$ **Stage 3** (1:1 co-located `*.test.ts(x)` & `src/mocks/handlers.ts`, verified via consolidated `npx vitest run <all-pending-test-files>`, `npm run typecheck`, & `npm run lint`) $\rightarrow$ **Stage 4** (Upstream ADRs & in-place superseded decision pruning in `docs/DECISIONS.md`, `scripts/generate-changelog.js`, and mandatory audit/update of `scripts/generate-architecture-matrix.js` & `scripts/lib/ast-parser.js` for both new files and behavioral/contract changes in existing modules — API route modes, storage/cookie caches, query-to-index paths, failure cascades, and hook/utility/component roles — because `npm run docs:sync` only executes the generator scripts and never edits their internal maps, plus static sections of `README.md`, `DEVELOPMENT.md`, `CONTRIBUTING.md`, `SECURITY.md`, `docs/PIPELINE_GUIDE.md`) $\rightarrow$ **Stage 5** (`npm run docs:sync`, `npm run gate:approve`, and `npm run security:audit`; if any check fails and fixes are applied, re-run affected Stage 3 checks, revisit Stage 4 docs/architecture generators, and re-run Stage 5 from `npm run docs:sync`).
