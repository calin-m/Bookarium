# Multi-Agent Development Standards - Bookarium

Welcome to **Bookarium**. When contributing or generating code for this repository, autonomous agents and developers must strictly follow these engineering protocols.

> **Canonical Protocol Specification & Full-Project Map**: For the complete enterprise governance rules and 6-layer system topology, see [`.agents/AGENTS.md`](file:///.agents/AGENTS.md) and [`docs/ARCHITECTURE.md`](file:///docs/ARCHITECTURE.md).

## Core Principles & Boundaries
1. **Rule 0 (User Approval, Pre-Plan Impact Audit & 6-Stage Plan Closure)**: Never modify files, apply architectural shifts, or install dependencies without prior user approval and review. Before drafting any new `implementation_plan.md`, inspect `git status --short` for undocumented pending changes from prior batches, trace interconnected files via the **Inter-Reference Impact Matrix**, and structure every plan in the **6-Stage Logical Execution Order (Zero-Drift Sequence)** (`Stage 0` through `Stage 5`) so approval covers sealing upstream generators and running `npm run docs:sync` in the same batch right after tests pass.
2. **Public Domain Integrity, Multi-Jurisdictional Copyright & Gutenberg Compliance**: Do not introduce any closed-source, DRM-restricted, or copyright-infringing book sources. Ensure all queries pass `copyright=false`, enforce multi-jurisdictional public domain evaluation (`src/lib/copyright-engine.ts`: `US 1930`, `Life+70`, `Life+80`, `Life+100`), preserve authentic author lifespans/names across local stores and IndexedDB (`isPlaceholderAuthor` guardrails so offline books never revert to `"Anonymous"` or trigger false `HTTP 451`), and strictly honor Project Gutenberg policy (individual-only downloads, mirror-first prioritization across `aleph.gutenberg.org`, `gutenberg.pglaf.org`, and `gutenberg.readingroo.ms` ahead of `www.gutenberg.org`).
3. **Zero API Key Requirement & Offline-First PWA Parity**: The core user experience must work without any third-party paid keys, auth sign-in, or backend database setup, and must maintain offline-first PWA resilience (`public/sw.js` `bookarium-app-shell-v4`, `useNetworkStatus`, adaptive offline Catalog fallback, and `isUnavailableOffline` restriction parity for uncached volumes when offline).
4. **State & Offline Architecture**:
   - **Remote data**: TanStack React Query v5 (`useBooks`, `useBookContent` with `networkMode: 'always'`, `useBookTranslations`).
   - **Local persistent state (10 Zustand stores)**: `useBookshelfStore`, `useReaderStore`, `useAuthStore`, `useFellowshipStore`, `useAnnotationStore`, `useAccoladesStore`, `useHabitsStore`, `useJurisdictionStore`, `usePreferencesStore`, and `useThemeStore`.
   - **Offline volume cache & cloud sync**: IndexedDB unabridged book storage (`src/lib/offline-storage.ts`, `useOfflineBooks`) and 6-store bi-directional Supabase outbox reconciliation (`src/lib/sync-utils.ts`, `src/lib/bookshelf-cloud-sync.ts`).
5. **Co-located Testing, Zero-Any, Zero-Warning & Anti-Regression Accuracy**: Every component (`*.tsx`), hook (`*.ts`), store (`*.ts`), route handler (`route.ts`), domain utility (`src/lib/**`), config (`src/config/**`), Web Worker (`src/workers/**`), and CLI data pipeline (`scripts/*.test.ts`) must have a 1:1 co-located `*.test.ts` or `*.test.tsx` testing authentic user journeys with `@testing-library/react` and MSW v2 (`194` suites). Zero synthetic/fake tests, no loose assertions, strict zero-`any` (`@typescript-eslint/no-explicit-any: "error"`), zero ESLint warnings (`--max-warnings 0`), CodeQL-safe relative asset URLs in tests, and mandatory co-evolution on every code change.
6. **Coverage Enforcement**: Never allow test coverage to drop below the configured V8 thresholds (`lines: 95%`, `statements: 95%`, `functions: 92%`, `branches: 85%`).
7. **Git Protocol (Human Execution Only)**: Provide in-depth structured conventional commit commands (`[PHASE]`, `[WHY]`, `[WHAT]`, `[VERIFICATION]`) only when explicitly requested by the user. AI agents must never execute `git commit` or `git push` directly.
8. **Two-Tier Test Execution, 7-Gateway Quality Engine & Post-Remediation Re-Sync Loop (`Rule 6`)**: Automatically run a consolidated pending-changes check (`npx vitest run <all-pending-and-colocated-test-files>`, `npm run typecheck`, `npm run lint`) across all modified/untracked files in `git status --short` upon completing each plan/batch (Stage 3) and prior to `npm run verify`. Run the full 194-suite `npm test` and 7-Gateway `npm run verify` (Pass 0.5 secret/boundary/env-parity/transitive-AST scanner, Pass 0.75 7-Pillar SAST/OWASP & 9-rule `bookarium-security` AST request-taint suite, and Passes 1–7 including semantic doc parity, 1:1 SQL$\leftrightarrow$TS schema parity, and 100% 1:1 test co-location) when explicitly requested by the user or when debugging a build/coverage error. Whenever a verification run reveals issues and remediation fixes are applied, re-check affected docs/generator scripts and re-run `npm run docs:sync` + verification so the post-fix state stays 100% synchronized.
9. **Rule 9 (Idempotent Database Schema Co-Evolution, RLS Governance & Live SQL Hand-Off)**: All database modifications must co-evolve `supabase/schema.sql`, `src/types/database.types.ts`, `scripts/generate-architecture-matrix.js`, and `README.md` using strictly idempotent SQL (`CREATE TABLE IF NOT EXISTS`, `CREATE INDEX IF NOT EXISTS`, `DROP POLICY IF EXISTS`) with strict Row Level Security enabled across all 14 tables (`SET search_path = ''` on all `SECURITY DEFINER` functions). Whenever `supabase/schema.sql` is modified, the agent must output a standalone, copy-paste-ready idempotent SQL migration block directly in chat so the user can immediately execute it in the deployed Supabase SQL Editor.
10. **Rule 1 (Two-Phase Documentation, Inter-Reference Matrix & 6-Stage Zero-Drift Sequence)**:
    - **Never Edit Generated Outputs Directly**: Never manually edit `docs/ARCHITECTURE.md`, `docs/GUTENBERG_PARSER.md`, `CHANGELOG.md`, `ROADMAP.md`, `docs/QUALITY_AUDIT_REPORT.md`, `docs/quality-audit-results.json`, or the auto-generated blocks in `README.md` (`<!-- BEGIN:architecture-diagrams -->`, `<!-- BEGIN:latest-release -->`, top telemetry badges/counts); always update their upstream sources first.
    - **6-Stage Logical Execution Order (Zero-Drift Sequence)**: Execute every approved plan bottom-up: **Stage 0** (`git status --short` & Inter-Reference Impact Audit across schema, `src/`, `.env.example`, `package.json`/`knip.json`/`.agents/hooks.json`, and security gates) $\rightarrow$ **Stage 1** (Contracts, `supabase/schema.sql`, `src/types/`, `.env.example`, configs, workflows) $\rightarrow$ **Stage 2** (Production `src/` & `scripts/` modules) $\rightarrow$ **Stage 3** (1:1 co-located `*.test.ts(x)` & `src/mocks/handlers.ts`, verified via consolidated `npx vitest run <all-pending-test-files>`, `npm run typecheck`, & `npm run lint`) $\rightarrow$ **Stage 4** (Upstream ADRs in `docs/DECISIONS.md`, generator lookup maps in `scripts/generate-*.js`, and static sections of `README.md`, `DEVELOPMENT.md`, `CONTRIBUTING.md`, `SECURITY.md`, `docs/PIPELINE_GUIDE.md`) $\rightarrow$ **Stage 5** (`npm run docs:sync`, `npm run gate:approve`, `npm run security:audit`, and `npm run lint`).
