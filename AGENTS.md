# Multi-Agent Development Standards - Bookarium

Welcome to **Bookarium**. When contributing or generating code for this repository, autonomous agents and developers must strictly follow these engineering protocols.

> **Canonical Protocol Specification & Full-Project Map**: For the complete enterprise governance rules and 6-layer system topology, see [`.agents/AGENTS.md`](file:///.agents/AGENTS.md) and [`docs/ARCHITECTURE.md`](file:///docs/ARCHITECTURE.md).

## Core Principles & Boundaries
1. **Rule 0 (User Approval, Pre-Plan Impact Audit & 6-Stage Plan Closure)**: Never modify files, apply architectural shifts, or install dependencies without prior user approval and review. Before drafting any new `implementation_plan.md`, inspect `git status --short` for undocumented pending changes from prior batches, perform an **All-of-`scripts/` Semantic Search** (paths, symbols, replaced legacy numeric/prose literals) and **Cross-Script / Reverse-Verifier Trace** across interconnected files (including additions, edits, renames, removals, `.github/workflows/*.yml`, and `PROTECTED_CONTRACTED_MODULES` [`TIER_1_CONTRACTED_MODULES` + `TIER_2_CONTRACTED_MODULES` + `TIER_3_CONTRACTED_MODULES` + `TIER_4_CONTRACTED_MODULES`]) via the **Inter-Reference Impact Matrix**, structure every plan in the **6-Stage Logical Execution Order (Zero-Drift Sequence)** (`Stage 0` through `Stage 5`), and explicitly enumerate in **Stage 4** which upstream generator scripts + exact internal lookup maps, non-map sections (Failure Mode / Caching Matrices, `scriptMetaMap`, `generate-roadmap.js` `MILESTONES[].features[]`), contract tables, Mermaid diagrams (`1`–`15`), or coupled verifier/gate scripts (`scripts/verify-build.js`, `scripts/lib/sast-validators.js`, `scripts/approval-gate.js`) change vs. remain auto-compiled, alongside which editable docs (`docs/DECISIONS.md`, `README.md`, `DEVELOPMENT.md`, `docs/INFRASTRUCTURE.md`, `docs/PIPELINE_GUIDE.md`, `docs/GITHUB_ACTIONS.md`, etc.) change and how.
2. **Public Domain Integrity, Multi-Jurisdictional Copyright & Gutenberg Compliance**: Do not introduce any closed-source, DRM-restricted, or copyright-infringing book sources. Ensure all queries pass `copyright=false`, enforce multi-jurisdictional public domain evaluation (`src/lib/copyright-engine.ts`: `US 1930`, `Life+70`, `Life+80`, `Life+100`), preserve authentic author lifespans/names across local stores and IndexedDB (`isPlaceholderAuthor` guardrails so offline books never revert to `"Anonymous"` or trigger false `HTTP 451`), eliminate browser-side and runtime Project Gutenberg traffic (`useOfflineCoverImage.ts` + `/api/books/content` strict R2 & optional Supabase serving via `src/lib/r2-client.ts` with zero runtime PG fallback), and strictly honor Project Gutenberg policy (individual-only offline downloads, `rsync` primary (`aleph.gutenberg.org` ↔ `rsync.ibiblio.org` failover) and official mirror fallback (`gutenberg.pglaf.org`, `aleph.gutenberg.org`, `gutenberg.readingroo.ms`) strictly in background CLI scripts with zero `www.gutenberg.org` fetching).
3. **Zero End-User API Key Requirement, Self-Hosted Storage Clarity & Offline-First PWA Parity**: The reader-facing experience must remain 100% free with zero third-party paid API keys, subscriptions, or mandatory sign-in *(developers deploying full online hosting require Supabase + private Cloudflare R2 storage exceeding Cloudflare's 10 GB free-tier allowance at 78k+ catalog scale, while local UI tests and offline IndexedDB previews run without external secrets — see `docs/INFRASTRUCTURE.md` for Mode 0–2 tiers, Free vs. Paid quotas, and hard platform coding guardrails)*, and must maintain offline-first PWA resilience (`public/sw.js` `bookarium-app-shell-v7`, `useNetworkStatus`, adaptive offline Catalog fallback, and `isUnavailableOffline` restriction parity for uncached volumes when offline).
4. **State & Offline Architecture**:
   - **Remote data**: TanStack React Query v5 (`useBooks`, `useFeaturedQuotes`, `useQuoteEnrichedBooks`, `useBookContent` with `networkMode: 'always'`, `useBookTranslations`).
   - **Local persistent state (10 Zustand stores)**: `useBookshelfStore`, `useReaderStore`, `useAuthStore`, `useFellowshipStore`, `useAnnotationStore`, `useAccoladesStore`, `useHabitsStore`, `useJurisdictionStore`, `usePreferencesStore`, and `useThemeStore`.
   - **Offline volume cache & cloud sync**: IndexedDB unabridged book storage (`src/lib/offline-storage.ts`, `useOfflineBooks`) and 7-store bi-directional Supabase outbox reconciliation (`src/lib/sync-utils.ts`, `src/lib/bookshelf-cloud-sync.ts`, `src/lib/preferences-sync.ts`).
5. **Co-located Testing, Zero-Any, Zero-Warning & Anti-Regression Accuracy**: Every component (`*.tsx`), hook (`*.ts`), store (`*.ts`), route handler (`route.ts`), domain utility (`src/lib/**`), config (`src/config/**`), Web Worker (`src/workers/**`), and non-exempt script under `scripts/` (`collectScriptFiles` minus `STANDALONE_RUNNER_SCRIPTS`: `scripts/ingest-*.test.ts`, `scripts/sync-*.test.ts`, `scripts/purge-vercel-cache.test.ts`, `scripts/scan-r2-content.test.ts`, `scripts/lib/*.test.ts`, `scripts/eslint-rules/bookarium-security.test.ts`) must have a 1:1 co-located `*.test.ts` or `*.test.tsx` testing authentic user journeys with `@testing-library/react` and MSW v3 (`271` suites). Standalone dev, doc, hook, and build runners (`STANDALONE_RUNNER_SCRIPTS`: `scripts/verify-build.js`, `scripts/generate-*.js`, `scripts/approval-gate.js`, `scripts/open-browser.js`) stay outside Vitest and `src/` V8 coverage (`vitest.config.mts`) to avoid circular self-invocation and coverage distortion. Zero synthetic/fake tests, no loose assertions, strict zero-`any` (`@typescript-eslint/no-explicit-any: "error"`), zero ESLint warnings (`--max-warnings 0`), CodeQL-safe relative asset URLs in tests, and mandatory co-evolution on every code change.
6. **Coverage Enforcement**: Never allow test coverage to drop below the configured V8 thresholds (`lines: 95%`, `statements: 95%`, `functions: 92%`, `branches: 85%`).
7. **Git Protocol (Human Execution Only, Live Diff Anti-Drift & `[PHASE]` Truthfulness)**: Provide in-depth structured conventional commit commands (`[PHASE]`, `[WHY]`, `[WHAT]`, `[VERIFICATION]`) only when explicitly requested by the user (citing a Roadmap Milestone in `[PHASE]` only when implementing a planned `ROADMAP.md` deliverable, or `<Descriptive Scope> (v<version>)` for tactical patch work). Before formulating any commit command, inspect **all** live working-tree changes directly from Git (`git status --short`, `git diff HEAD` covering both staged and unstaged tracked deltas, and direct reads of all `??` untracked files) — never draft commit messages from conversation context or prior summaries — and ensure `[WHAT]`/`[WHY]` cover 100% of current pending changes (paired with a concise grouped file summary, printing raw unified patches only when requested) while `[VERIFICATION]` reports only checks observed on the current pending state. AI agents must never execute `git commit` or `git push` directly.
8. **Two-Tier Test Execution, 7-Gateway Quality Engine & Post-Remediation Re-Sync Loop (`Rule 6`)**: Automatically run a consolidated pending-changes check (`npx vitest run <all-pending-and-colocated-test-files>`, `npm run typecheck`, `npm run lint`) across all modified/untracked files in `git status --short` upon completing each plan/batch (Stage 3) prior to Stage 4/Stage 5 and `npm run verify`. Run the full 271-suite `npm test` and 7-Gateway `npm run verify` (Pass 0.5 secret/boundary/env-parity/transitive-AST scanner, Pass 0.75 7-Pillar SAST/OWASP, offline `GPL`/`AGPL` lockfile license SCA, CLI `scripts/` checks, `sast-validators.js` AST suite, & 9-rule `bookarium-security` AST request-taint suite, Passes 1–6 including semantic doc, relative Markdown link, SQL explicit index / `jurisdictionBaselines`, `README.md` Diagram 1, & circular `SECURITY.md` parity, `.husky/pre-commit` static check via `npm run gate:approve`, 0 broken Mermaid diagrams, 1:1 SQL$\leftrightarrow$TS schema parity, and 100% 1:1 test co-location, plus Pass 7 compiled `.next/routes-manifest.json` & live `127.0.0.1` HTTP smoke probe) when explicitly requested by the user or when debugging a build/coverage error. Whenever a Stage 5 or verification run reveals issues and remediation fixes are applied, loop back through affected Stage 3 checks (`vitest`, `typecheck`, `lint`), revisit Stage 4 docs/architecture generator scripts, and re-run Stage 5 (`npm run docs:sync`, `npm run gate:approve`, `npm run security:audit`) so the post-fix state stays 100% synchronized.
9. **Rule 9 (Idempotent Database Schema Co-Evolution, RLS Governance, Account Deletion Parity & Live SQL Hand-Off)**: All database modifications must co-evolve `supabase/schema.sql`, `src/types/database.types.ts`, `scripts/generate-architecture-matrix.js`, and `README.md` using strictly idempotent SQL (`CREATE TABLE IF NOT EXISTS`, `CREATE INDEX IF NOT EXISTS`, `DROP POLICY IF EXISTS`) with strict Row Level Security enabled across all 14 database tables (13 `public.*` tables + `supabase_migrations.schema_migrations`) (`SET search_path = ''` and `REVOKE EXECUTE ... FROM PUBLIC, anon` on all `SECURITY DEFINER` functions, plus `REVOKE EXECUTE ... FROM PUBLIC, anon, authenticated` on all `RETURNS TRIGGER` functions). Every user-scoped table, column, or local store slice must also maintain 100% account deletion parity (`ON DELETE CASCADE`, explicit purge in `public.delete_current_user()`, fallback deletion in `useAuthStore.deleteAccount()`, and complete local store/device reset in `clearLocalUserStores({ wipeDeviceStorage: true })`). Whenever `supabase/schema.sql` is modified, the agent must output a standalone, copy-paste-ready idempotent SQL migration block directly in chat so the user can immediately execute it in the deployed Supabase SQL Editor.
