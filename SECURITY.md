# Security Policy

The Bookarium engineering team takes the security and integrity of our application, user data, and public domain catalog seriously. This policy outlines supported versions and our responsible disclosure protocol.

---

## Supported Versions

Security patches, dependency updates, and bug fixes are applied to the active release stream on the `master` branch.

| Version | Supported | Notes |
|---|:---:|---|
| **2.9.x** | ✅ | **Active Release** (Recommended for all users and deployments) |
| < 2.9.0 | ❌ | Older releases are not actively maintained; please upgrade to the latest release |

---

## Reporting a Vulnerability

If you discover a security vulnerability, security bug, or potential data exposure in **Bookarium**, please disclose it responsibly.

### ⚠️ Please Do NOT Open a Public Issue
Never disclose potential security vulnerabilities through public GitHub issues, pull requests, or public discussions.

### Preferred Reporting Method: GitHub Private Vulnerability Advisories
GitHub provides a secure, private advisory workflow for public repositories:
1. Navigate to [**github.com/calin-m/Bookarium/security/advisories**](https://github.com/calin-m/Bookarium/security/advisories).
2. Click **Report a vulnerability**.
3. Provide a detailed summary, including:
   - Description of the vulnerability and its potential impact
   - Clear, reproducible proof-of-concept steps or payload
   - Browser environment, device, or API endpoints affected
   - Any suggested remediations or patches

### Response Timeline
- **Initial Acknowledgement**: Within 48 hours of receiving the report.
- **Triage & Assessment**: Within 5 business days, confirming severity and validity.
- **Resolution & Release**: A security patch will be prepared on a private branch and released alongside an official CVE/GitHub Security Advisory once verified.

## Security Architecture & Core Safeguards

Bookarium incorporates multi-layered security controls designed into its architecture and synchronized deterministically from live source AST (`scripts/generate-architecture-matrix.js` via `npm run docs:sync`) and enforced in `Pass 5` (`auditSecurityDocumentationParity`):

1. **Zero Secret Footprint, Trojan Source Defense, Env Parity & Transitive Boundary Isolation (Pass 0.5 Scanner)**:
   - Automated pre-commit scanning (`scripts/verify-build.js`) prevents accidental commits of API keys, RSA/EC/OpenSSH private keys, fine-grained GitHub PATs (`github_pat_`), Supabase tokens (`sbp_`, `sbs_`, `sb_secret_`), Cloudflare R2 / AWS S3 credentials (`AKIA`/`ASIA`, `r2_access_key_id`, `r2_secret_access_key`), OpenAI/Anthropic (`sk-proj-`, `sk-ant-`), Google Cloud/Gemini (`AIza`), npm (`npm_`), Vercel (`vercel_`), and Stripe (`sk_live_`, `rk_live_`) tokens, Base64URL-decoded Supabase `service_role` JWTs, Slack/Discord webhooks, PostgreSQL connection strings with embedded credentials, Unicode Trojan Source bidirectional overrides (`CVE-2021-42574`) and hidden zero-width control characters, tracked `.env*`/`.pem`/`.key` files, oversized binaries (`> 5 MB`), undocumented `NEXT_PUBLIC_*` / `NEXT_PUBLIC_R2_*` variables (`validateEnvAndPrivilegeBoundariesAst` against `.env.example`, blocking `SUPABASE_SERVICE_ROLE_KEY`, `R2_ACCESS_KEY_ID`, and `R2_SECRET_ACCESS_KEY` in client modules), or direct/transitive client$\to$server AST dependency leaks (`src/lib/supabase/server.ts`, `src/lib/supabase/middleware.ts`, `src/lib/r2-client.ts`, `next/headers`, `fs`, `child_process`, `zlib`, `net`, `tls`).
2. **7-Pillar OWASP Pre-Commit SAST, Supply-Chain License SCA & 9-Rule AST Taint Suite (Pass 0.75 & Pass 7)**:
   - Automated pre-commit gates (`npm run security:audit`, `scripts/lib/sast-validators.js`, and `scripts/eslint-rules/bookarium-security.js`) enforce seven security pillars alongside a custom 9-rule ESLint & Babel AST engine (7 security/taint rules + 2 engineering/policy governance rules, reported distinctly from `Pass 5` documentation/governance checks):

     2. **API Route Rate Limiting, Security Header Parity, Boundary Isolation & Zero-External-PG SSRF Guard (`no-unsafe-fetch`, `no-client-server-boundary-violation`, `no-secret-env-or-public-route-leak`)**: Verifies `RateLimiter.check()`, `buildApiSecurityHeaders()`, `sameSite`/`secure` cookie flags across both function-declaration and `export const GET|POST|...` arrow route handlers (`validateApiRoutesSecurityAst`), `@/lib/server-rsc-nav` / `node:http(s)` client isolation, and strict R2-only upstream endpoint verification (`redirect: 'manual'`, `isAllowedR2EndpointUrl()`), banning runtime Project Gutenberg and `gutendex.com` fetches across `/api/books/content`, `/api/books`, and `/api/books/translations` (`ADR-080`, `ADR-084`).
     3. **DOM XSS, Reverse Tabnabbing, ReDoS, Double-Escaping & CLI Execution Guard (`no-dangerous-execution`, `no-unsafe-dom-injection`)**: Blocks `eval()`, `new Function()`, string-based `setTimeout`/`setInterval`, `{ shell: true }` and raw shell spawns in `src/` and `scripts/` (requiring shell-free `spawn(..., { shell: false })` + `sanitizeLocalDevUrl` in `scripts/open-browser.js`), catastrophic backtracking ReDoS regex literals and static `new RegExp()` literals (`CWE-1333`), `dangerouslySetInnerHTML`, `.innerHTML =`, `.outerHTML =`, `iframe.srcdoc`, `.setAttribute('srcdoc'|'href'|'src', ...)`, `document.write()`, `.insertAdjacentHTML()`, `.createContextualFragment()`, chained XML/HTML entity `.replace()` double-escaping and double-unescaping (`CWE-116` / `js/double-escaping`), static, TS-cast/constant-folded, and dynamic JSX `href`/`src` URI scheme expressions (`javascript:`/`vbscript:`/`data:text/html,`), `<a target="_blank">` / `window.open(..., '_blank')` missing `noopener`/`noreferrer` (`CWE-1022`), and wildcard `postMessage(data, '*')` (`CWE-345`), while `sanitizeBookFormatUrl()` constrains client format URLs (`extractBookFormats`) to `https:` (plus opt-in `blob:` exclusively for offline cover previews).
     4. **Open Redirect Sanitization, Categorized Sanitizers & Server/Client/CLI Request Taint Analysis (`no-unvalidated-redirect`, `no-tainted-request-sink`)**: Enforces `sanitizeRedirectPath` and `resolveCanonicalAuthOrigin` (`src/lib/redirect-sanitizer.ts`, `validateRedirectRoutesAst`) on all redirects and performs flow-sensitive AST taint tracking across server request sources (`request params`, `searchParams.get()`, `headers.get()`, `cookies.get()`, `request.json()`), client navigation sources (`useSearchParams().get()`, `document.referrer` -> `router.push()`/`replace()` exempting static non-protocol-relative `/path` and `ROUTES.*` prefixes), and CLI `scripts/` `process.argv` inputs (to `shell`, `fetch`, Node `https.get`/`http.get`, `redirect`, PostgREST `.or()`/`.filter()` filter strings `CWE-943`, dynamic `new RegExp()` `CWE-1333`, file system access, external URLs, and Prototype Pollution computed writes) using categorized sanitizer sets with array/conditional sanitizer intersection (`getNodeSanitizedSinks`).
     5. **MIT License, Public Domain (`copyright=false`), Zero-PG-Runtime Policy & 78k-Row Index Query AST Guard (`enforce-gutenberg-and-copyright-policy`)**: Verifies `package.json` MIT licensing, validates `copyright !== true` filtering via AST (`validatePublicDomainFilterAst`), blocks `copyright=true` in query strings or `URLSearchParams`, forbids all runtime `fetch()` calls to Project Gutenberg or PG mirror domains inside `src/**` (and forbids `www.gutenberg.org` / `gutenberg.org` `fetch()` across both `src/` and `scripts/`, keeping background CLI tools restricted to multi-host `rsync` (`aleph.gutenberg.org`/`rsync.ibiblio.org`) and official HTTPS mirrors `aleph.gutenberg.org`/`gutenberg.pglaf.org`/`gutenberg.readingroo.ms`), and enforces 78k-row `public.books` index query invariants (forbidding secondary SQL `.order('id')` chained onto `.order('download_count')` and requiring a Primary Key `.in('id', chunk)` bound whenever `.neq('quotes', '[]')` is combined with `.order('download_count')`).
     6. **PostgreSQL Row Level Security (RLS), `InitPlan` Policy Optimization, Trigger RPC Isolation, Fellowship Column Guards, Owner-Scoped Session RPCs & 4-Layer Rule 9 Teardown Parity**: Statically verifies `ENABLE ROW LEVEL SECURITY` across all 14 database tables (13 public tables + `supabase_migrations.schema_migrations`), 100% DDL/policy/trigger idempotency (`CREATE TABLE IF NOT EXISTS`, `CREATE INDEX IF NOT EXISTS`, `DROP POLICY IF EXISTS`, `DROP TRIGGER IF EXISTS`), `(select auth.uid())` `InitPlan` scalar subquery wrapping (`0003_auth_rls_initplan`) and single-permissive-policy-per-action consolidation (`0006_multiple_permissive_policies`), scoped write-RLS isolation, `SET search_path = ''` and `REVOKE EXECUTE ... FROM PUBLIC, anon` across all `SECURITY DEFINER` functions (including owner-scoped session inspection/revocation RPCs `public.get_active_sessions()` with SQL-level IP masking and `public.revoke_user_session(UUID)`), full PostgREST RPC revocation (`REVOKE EXECUTE ...      7. **OWASP HTTP Security Headers, Compiled Manifest Parity, Live Loopback HTTP Probe & Service Worker AST Guard**: Verifies all 7 hardened security headers (`Content-Security-Policy`, `Strict-Transport-Security`, `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy`, `Cross-Origin-Opener-Policy`) with CSP `object-src 'none'`, `frame-ancestors 'none'`, `form-action 'self'`, `base-uri 'self'`, `isDev`-gated `unsafe-eval` stripping, `!isDev` HSTS, and `X-Frame-Options: DENY` in `next.config.ts` via Babel AST (`validateNextConfigSecurityHeadersAst`), compiled `.next/routes-manifest.json` parity (`validateNextBuildHeaderManifest` in `Pass 7`), live loopback `127.0.0.1` `next start` response probing (`validateLiveHttpSecurityResponse` verifying runtime OWASP headers, `403` Fetch Metadata anti-deeplink/cross-site rejections, `400` SSRF/param/invalid-ID rejections, and origin-locked `/auth/callback` redirects), and Babel AST verification of `public/sw.js` (`validateServiceWorkerSecurity`: strict cross-origin pass-through, bounded `CACHE_URLS` same-origin sanitization `<= 100` excluding `/auth/` and `/api/`, non-GET bypass, zero `importScripts()`/`eval()`).
3. **Continuous Cloud Code Scanning & PR Supply-Chain Review (GitHub CodeQL & Dependency Review)**:
   - [`.github/workflows/codeql.yml`](.github/workflows/codeql.yml) (`push`/`pull_request` on `main`/`master`/`dev` + `cron: 30 1 * * 1`) continuously analyzes `javascript-typescript` and `actions` workflows into GitHub Security SARIF alerts, while [`.github/workflows/dependency-review.yml`](.github/workflows/dependency-review.yml) gates PRs against high/critical dependency CVEs and incompatible copyleft (`GPL`/`AGPL`) licenses.

7. **Automated Validator, Policy & Custom ESLint Rule Inventory (AST-Synced)**:
