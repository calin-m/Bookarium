# Enterprise Master Governance & Agent Operations Protocol - Bookarium

This document establishes immutable engineering rules, governance procedures, operational guardrails, and a 6-layer system topology reference for all human developers and autonomous AI coding agents interacting with this repository.

---

## 1. Core Governance Rules

### Rule 0: Mandatory User Approval, Pre-Plan Impact Audit & 6-Stage Zero-Drift Execution Sequence
- **Approval-First Execution:** The AI agent must never modify existing files, create new files, perform destructive actions, apply architectural mutations, or install unexpected dependencies without explicit prior user approval and review.
- **Pre-Plan Pending Diff Audit, Scalability Impact Check, 6-Stage Layout & Stage-4 Plan Completeness Contract:** Before generating any new `implementation_plan.md`, the AI agent must inspect `git status --short` for existing uncommitted changes from previous batches (folding any undocumented pending changes into the plan), perform an **All-of-`scripts/` Semantic Search** (across paths, symbols, and replaced legacy numeric/prose literals) and **Cross-Script / Reverse-Verifier Trace** across `scripts/**/*.js` and `docs/*.md`, trace every affected file through the **Inter-Reference Impact Matrix** (`Rule 1`), evaluate scaling implications across PostgreSQL/DB, Edge/API/R2, Client/Offline PWA, and CI (`Rule 10`), and lay out the plan using the **6-Stage Logical Execution Order (Zero-Drift Sequence)** (`Stage 0` through `Stage 5`) so Rule 0 approval covers sealing documentation and running generators in the exact bottom-up order immediately after tests pass. Every plan's **Stage 4** MUST explicitly enumerate:
  1. **Upstream Generator Scripts & Exact Internal Targets**: Each touched generator (`scripts/generate-architecture-matrix.js`, `scripts/lib/ast-parser.js`, `scripts/generate-changelog.js`, `scripts/generate-roadmap.js`, `scripts/generate-quality-report.js`, `scripts/generate-parser-docs.js`, `scripts/generate-contracts-docs.js`), **exact internal lookup maps, non-map sections (Failure Mode & Caching matrices, contract tables, or Mermaid diagrams (`1`–`16`)** to modify and how, plus any coupled verifier/gate assertions (`scripts/verify-build.js`, `scripts/lib/sast-validators.js`, `scripts/approval-gate.js`) and confirmation of which generators need no manual edits beyond running `npm run docs:sync`.
  2. **Manual Documentation vs. Auto-Compiled Outputs**: Each directly edited guide/record (`docs/DECISIONS.md` ADR ID + item number, `README.md`, `DEVELOPMENT.md`, `docs/PIPELINE_GUIDE.md`, `docs/GITHUB_ACTIONS.md`, `CONTRIBUTING.md`, `SECURITY.md`, `.env.example`, `.github/pull_request_template.md`, `.github/ISSUE_TEMPLATE/*.yml`, `AGENTS.md`, `.agents/AGENTS.md`) with exact sections/changes, separated clearly from auto-compiled targets (`docs/ARCHITECTURE.md`, `docs/architecture/*.md`, `docs/GUTENBERG_PARSER.md`, `docs/SYSTEM_CONTRACTS.md`, `CHANGELOG.md`, `ROADMAP.md`, `docs/QUALITY_AUDIT_REPORT.md`, `docs/quality-audit-results.json`).
- **Proposal & Review:** The AI agent must propose technical plans, explain trade-offs and diffs clearly, and obtain explicit user consent before proceeding with any code edits.
- **Deterministic Hook Enforcement:** All file mutations (`write_to_file`, `replace_file_content`) are gated by `.agents/hooks.json` (`scripts/approval-gate.js`) and verified prior to release.
- **Human Developer Authority:** The human developer retains final authority over all codebase changes, architectural decisions, and terminal command executions.

### Rule 2: Zero-Bloat & AST-Driven Single Source of Truth
Never manually craft static component matrices, route catalogs, or architectural dependency diagrams that can drift.

- No mock data or dead prototypes in production code paths.

### Rule 3: Strict Testing, Coverage Co-location, Zero-Any & Anti-Regression Accuracy
- **Mandatory Co-Evolution:** Whenever UI copy, component interfaces, DOM hierarchy, state structures, or user flows are modified, the co-located `*.test.ts` or `*.test.tsx` files MUST be updated in the same changeset to reflect the exact new behavioral contract across components (`src/components/**`), pages/routes (`src/app/**`), hooks (`src/hooks/**`), stores (`src/stores/**`), domain utilities (`src/lib/**`), configs (`src/config/**`), Web Workers (`src/workers/**`), and CLI ingestion/sync & AST security pipelines (`scripts/ingest-*.test.ts`, `scripts/sync-*.test.ts`, `scripts/eslint-rules/bookarium-security.test.ts`; standalone verify/generator/hook runners stay outside Vitest and `src/` V8 coverage to avoid circular execution).
- **Zero Synthetic / Fake Tests (Anti-Tautology Protocol):** Tests must assert genuine user journeys, accessible roles (`getByRole`), state mutations, or router actions. Strictly prohibit tautological tests (e.g. `expect(true).toBe(true)`), shallow snapshot-only tests, or meaningless assertions designed solely to inflate coverage numbers.
- **No False Positives (Strict Verification):** Never loosen assertions (e.g. replacing a precise element check with an overly generic query or catch-all wildcard) just to force a failing test to pass. Tests must fail if the feature, label, accessibility contract, or state handler is broken.
- **No False Negatives (Deterministic Isolation):** Ensure component and hook tests use MSW v3 network isolation (`src/mocks/server.ts`, `src/mocks/handlers.ts`) and `@testing-library/react` without flaky timing, unhandled React `act(...)` warnings, or external network dependencies. Use root-relative asset paths (e.g. `/_next/static/...`) rather than unencrypted `http://` URLs when constructing DOM `<script>` / `<link>` elements in tests to satisfy CodeQL (`js/functionality-from-untrusted-source`).
- **Zero-Any & Zero-Warning Gate:** Strictly forbid explicit `any` (`@typescript-eslint/no-explicit-any: "error"`) and enforce zero ESLint warnings (`eslint . --max-warnings 0`).
- **Coverage Floor:** Test coverage must never drop below the configured V8 thresholds (`lines: 95%`, `statements: 95%`, `functions: 92%`, `branches: 85%`). Co-location is strictly enforced across all executable modules.

### Rule 4: End-User Keyless Reading, Self-Hosted R2/Supabase Clarity, Multi-Jurisdictional Copyright & Project Gutenberg Compliance
- **Public Domain & End-User Zero Paid API Keys:** All book metadata and content fetching must strictly enforce `copyright=false` or verify public domain status (Zero-Copyright / CC0 / Project Gutenberg Public Domain). Never require end-user API keys, third-party subscriptions, or mandatory authentication for browsing, reading, or downloading *(full self-hosted production deployments require configuring Supabase and private Cloudflare R2 storage exceeding R2's 10 GB free-tier allowance, while local UI tests and offline IndexedDB previews operate without external keys — consult `docs/INFRASTRUCTURE.md` for Mode 0–2 tiers, Free vs. Paid provider quotas, and hard platform coding guardrails)*.
- **Multi-Jurisdictional Copyright & Author Lifespan Self-Healing:** Preserve multi-jurisdictional copyright gatekeeping (`src/lib/copyright-engine.ts`: `US 1930`, `Life+70`, `Life+80`, `Life+100`, joint authorship Art. 7bis, translator protection Art. 2(3)) and non-regressive author/lifespan merge guardrails (`isPlaceholderAuthor` checks across `useContinueReadingLedger.ts`, `offline-storage.ts`, `useOfflineBooks.ts`, `useReaderStore.ts`, and `useBookshelfStore.ts`) so offline or refreshed books never revert to `"Anonymous"` or trigger false `HTTP 451` errors.
- **Project Gutenberg Policy, Strict Private R2 Asset Serving & Zero-HTTPS Bulk Compliance:** Strictly enforce individual-only offline downloads (never introduce batch shelf downloaders or automated mass scrapers), route runtime covers (`type=cover`) and plain-text books strictly through private Cloudflare R2 (`src/lib/r2-client.ts`, failing closed `404`/`503` without runtime Project Gutenberg fallback or browser cover hotlinking), confine bulk Project Gutenberg text/cover downloads exclusively to background `rsync` / `wsl-rsync` pipelines (`aleph.gutenberg.org` ↔ `rsync.ibiblio.org` failover in `sync-r2-assets.js`) and weekly catalog CSV/RDF feeds (`gutenberg.pglaf.org`, `aleph.gutenberg.org` in `sync-gutenberg-catalog.js`) with zero bulk HTTP mirror or `www.gutenberg.org` scraping, run `sync-featured-quotes.js` strictly against private R2 (`--source=r2`), preserve `SITE_CONFIG.USER_AGENT` / catalog UA attribution on allowed CLI feeds, and retain the Project Gutenberg license/colophon section (`preBody` + `postBody` in `Colophon & License`) in segmented texts.
- **Offline-First PWA Parity:** Maintain offline App Shell resilience (`public/sw.js` `bookarium-app-shell-v7`, `ServiceWorkerRegister.tsx`, `useNetworkStatus.ts`), adaptive offline Catalog fallback (serving IndexedDB downloaded volumes when cached books exist or `CatalogOfflineView.tsx` when empty), and `isUnavailableOffline` restriction parity (cover/spine dimming, `Not Downloaded` badges, and disabled read/download triggers for uncached volumes when offline).

### Rule 5: Conventional Commit Formatting & User-Driven Commit Execution Protocol
- **Agent Prohibition:** The AI agent is strictly prohibited from executing `git commit`, `git push`, `git merge`, or branch-modifying Git commands directly.
- **On-Demand Command Formulation Only:** The AI agent must only generate and provide Git commit commands when explicitly requested by the user (e.g. when the user asks "how do I commit this?", "generate commit command", or asks to commit a completed step). The agent must NOT automatically append git commands to general Q&A or intermediate discussion turns.

### Rule 10: Full-Stack Scalability & Growth Architecture Standard
Every schema change, API route, client store, offline cache, and automation pipeline must be designed to scale cleanly from early adopters to `10k–100k+` accounts without inflating storage, database CPU, serverless egress, or client memory:
- **PostgreSQL & Data Modeling Scalability**:
  - **Single Source of Truth vs. Deliberate Denormalization**: Do not duplicate mutable identity or bibliographic attributes across user/social tables when a batched `O(log N)` Primary Key lookup (`profiles_pkey`, `books_pkey`) resolves them without violating RLS privacy boundaries (reserve deliberate denormalization strictly for read-heavy batch-ingested catalog arrays/GIN vectors in `public.books` or RLS privacy boundaries like `user_reading_habits.completed_books_count`).
  - **Exact Query-to-Index Alignment**: Verify every new query, filter, sort, RLS `EXISTS` predicate, and RPC matches an index's leading column order, exact expression (e.g., `lower(trim(p.username))`), and partial predicate (`WHERE ... IS NOT NULL`), and enforce symmetric relationship uniqueness at the database layer via undirected functional indexes (`LEAST(...)`, `GREATEST(...)`).
  - **Write Amplification, Native Types & Lean Keys**: Keep high-frequency write tables (`reading_progress`) lean and free of multi-row cascade triggers; prefer compact native PostgreSQL types (`DATE[]`, `INTEGER`/`SMALLINT`) over `JSONB` string arrays or bit-packed `NUMERIC` fields; and prefer natural composite primary keys over redundant surrogate `id UUID` primary keys on 1:1 and M:N tables.
- **Edge, CDN, R2 & Serverless API Scalability**:
  - Use explicit slim column allowlists (avoiding unbounded `SELECT *` on catalog or multi-table lookups), coalesce concurrent cold misses per key (`coalesceInFlight` / `coalesceInFlightByUser`), enforce bounded `globalThis` LRU / `unstable_cache` TTLs with fail-closed `Cache-Control: no-store` on degraded/error responses, short-circuit unsupported or out-of-bounds requests before hitting PostgreSQL or R2, and enforce per-route rate limits with zero unpaginated fan-outs.
- **Client, State & Offline PWA Scalability**:
  - Bound all `localStorage` and IndexedDB caches with explicit entry/byte caps and TTL pruning (`MAX_CACHED_COVERS`, bounded quote pools, zero unbounded outbox/history growth), debounce and batch cloud writes behind passive cooldowns (`PASSIVE_SYNC_COOLDOWN_MS`), sanitize persisted offline outbox payloads on rehydration/flush so schema retirements never fail on returning offline PWAs, offload heavy parsing to Web Workers (`gutenberg.worker.ts`), and code-split secondary modals/drawers (`next/dynamic`).
- **Build, CI & Zero-Downtime Rollout Scalability**:
  - Maintain exact-diff incremental ingestion (`catalog-cache` RAM diffing, R2 delta syncs), bounded concurrency (`DEFAULT_R2_PUT_CONCURRENCY`, Vitest worker limits), and expand-and-contract deployment sequencing (code stops writing retired columns before DDL drops them) so live users experience zero downtime.
